# 2026-08-28 — GitHub/LinkedIn doğrulama; Users’ta Admin rolü

## Ne yapmayı planladın?

- GitHub girişini uçtan uca doğrulamak (App ID, User Secrets, admin’de aç).
- Çalışırsa LinkedIn’i aynı üç adımla bağlamak.
- Users sayfasını gerçek rol atamasına bağlamak: Admin yap / Admin’i al.

## Hangi sorunlar ile karşılaştın?

- Sabah uygulama kapalıydı; MSSQL konteyneri açıktı.
- LinkedIn’de client secret, “Secret store key” alanına yapıştırıldı. O alan secret’ın kendisi değil, User Secrets’taki anahtarın adı; buton bu yüzden çıkmadı.
- Users ve Roles yalnızca listeydi; bir hesabı Admin yapmak için veritabanına elle yazmak gerekiyordu.

## Bu sorunları nasıl çözdün?

- Uygulamayı `dotnet run --project src/TablerAuth.Web --launch-profile https` ile açtım.
- GitHub: girişte buton var, admin “On the login page”, challenge `github.com`’a `redirect_uri=https://localhost:7258/signin-github` ve `read:user user:email` ile gidiyor.
- LinkedIn: secret User Secrets’a alındı, formdaki anahtar doğru isme çekildi. Girişte Google / GitHub / LinkedIn butonları var; LinkedIn `linkedin.com`’a `openid profile email` ile gidiyor.
- Users’a Make Admin / Remove Admin eklendi. Son Admin alınamıyor. User `/Users` yazınca 403.
- Şifre sıfırlama sahte sayfa olmaktan çıktı (Development’ta reset linki sayfada). Kayıtta da dış giriş butonları var. Sağlayıcı formuna “buraya secret yapıştırma” reddi eklendi. Remember me 14 gün. Tema aç/kapa, Dashboard sade, hesap bilgisi Profile’da.
